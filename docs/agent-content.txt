# Zil Documentation — Agent-Friendly Reference
# https://getzil.dev/docs
# Source: https://github.com/fluentdata-co/zil
# Package: pip install zil-ai
# Version: 0.1.19

## Overview

Zil is an open-source framework for building, validating, packaging, and
deploying production AI agents. It composes with Google ADK, A2A, MCP,
DeepEval, and OpenTelemetry.

This document contains the full technical reference in a format optimized
for AI agents and LLMs.

---

## Install

    pip install zil-ai              # CLI only
    pip install 'zil-ai[adk]'       # CLI + SDK + Google ADK (default)
    pip install 'zil-ai[openhands]' # CLI + SDK + OpenHands
    pip install 'zil-ai[adk,serve]' # CLI + SDK + ADK + FastAPI server

Requires Python 3.11+.

## CLI Reference

### zil init

Scaffold a new agent project.

    zil init <name> [options]

Options:
    --llm              gemini | anthropic | openai | vertex  (default: gemini)
    --framework        adk | openhands                        (default: adk)
    --mcp              none | filesystem | git | custom       (default: none)
    --agents           Comma-separated sub-agent names (e.g. vta,vtd)
    --skills           Comma-separated skill names (e.g. fd-submit-changes,fd-run-tests)
    --service          none | webhook                         (default: none)
    --no-evals         Skip eval suite scaffolding
    --no-otel          Skip OpenTelemetry instrumentation
    --non-interactive  Use defaults for all prompts

Generated files:
    manifest.yaml, adapters/llm.yaml, adapters/embed.yaml,
    identity/persona.md, identity/instructions.md, identity/guardrails.yaml,
    evals/baseline.yaml, evals/cases/accuracy.yaml, evals/cases/tool_use.yaml,
    evals/cases/escalation.yaml, observability/config.yaml,
    {module_name}/__init__.py, {module_name}/agent.py, {module_name}/.env.example,
    Dockerfile, requirements.txt, .github/workflows/zil-pipeline.yaml,
    README.md, .gitignore

With --agents: agents/{name}/identity/ dirs, spec.agents in manifest.
With --service webhook: {module_name}/app.py (FastAPI), {module_name}/runner.py.
With --skills: skills/{name}/SKILL.md stubs, spec.skills in manifest.

After scaffolding, creates a .venv and installs dependencies.

### zil validate

Validate a project against the manifest schema.

    zil validate [options]

Options:
    --project-dir DIRECTORY  Project directory (default: .)
    --format        text | json                   (default: text)

Exit codes: 0 = valid, 1 = errors, 2 = warnings only.

Checks:
1. Manifest schema — manifest.yaml against the Zil v1 JSON Schema
2. Identity files — persona.md, instructions.md, guardrails.yaml exist
3. Guardrails — structure, enforceable rule count, regex validity
4. Adapter references — LLM and embedding adapter YAML files exist
5. Eval suite — baseline.yaml and referenced case files exist
6. Observability config — config.yaml exists, recommended attributes
7. Environment variables — spec.env declarations, adapter cross-refs
8. MCP tools — source dirs, entry_point files, env var references
9. Multi-agent — spec.agents identity dirs, LLM model refs, MCP server refs
10. Runtime deps — unknown types, npm-global without apt-nodesource
11. Cost config — budget consistency checks

### zil audit

Agent-native security audit — focused on LLM-specific attack surfaces.

    zil audit [options]

Options:
    --project-dir DIRECTORY  Project directory (default: .)
    --format        text | json                   (default: text)
    --fix           Show actionable fix suggestions

Exit codes: 0 = pass, 1 = critical findings, 2 = warnings only.

Checks:
1. Guardrail coverage — scores 5 dimensions (injection, PII output,
   PII input, output constraints, denied topics)
2. Injection resilience — runs 20 adversarial prompts through the
   guardrail engine across 6 attack categories
3. Output leakage — checks if system prompt/persona/instructions
   could leak through output undetected
4. Indirect injection surface — AST-scans tool functions for
   external data ingestion (HTTP, DB, file reads) without guardrails
5. Instruction consistency — detects contradictions between
   permissive persona language and restrictive guardrails
6. Context window risk — measures system prompt size vs model context
7. Identity hardening — checks for anti-patterns in identity files

### zil pack

Build a .zil archive.

    zil pack [options]

Options:
    --project-dir DIRECTORY  Project directory (default: .)
    --output-dir DIRECTORY   Output directory (default: dist/)
    --skip-evals             Skip eval suite (warns)
    --sign                   Sign the archive with cosign after building
    --key PATH               Path to cosign private key (default: keyless/OIDC)

Steps:
1. Validate project against manifest schema
2. Cross-check .env files against spec.env declarations
   - FAIL if .env files contain undeclared vars (config drift)
   - WARN if spec.env vars are missing from .env files
3. Run eval suite (gate — blocks if below threshold)
4. Generate CycloneDX 1.5 SBOM from requirements.txt
5. Create versioned .zil tar.gz archive in dist/

Env coverage results are recorded in BUILD_META.json inside the archive.

### zil inspect

Inspect a .zil archive without extracting.

    zil inspect <archive> [options]

Options:
    --show COMPONENT  Print a specific component
    --json            Machine-readable JSON output
    --verify          Verify the cosign signature of the archive
    --key PATH        Path to cosign public key for verification

### zil serve

Start the agent as a REST/A2A server.

    zil serve [options]

Options:
    --project-dir DIRECTORY  Project directory (default: .)
    --port INTEGER           Server port (default: 8000)
    --host TEXT              Bind address (default: 127.0.0.1)
    --no-a2a                 Disable A2A protocol endpoints
    --reload                 Auto-reload on code changes (dev mode)
    --docker                 Build and run in Docker container
    --trace                  Enable OTLP trace export
    --trace-console          Print spans to stderr (no collector needed)

Endpoints:
    GET  /health                    Health check
    POST /invoke                    One-shot invoke (SSE stream)
    POST /sessions                  Create session
    POST /sessions/{id}/messages    Send message (SSE stream)
    GET  /sessions/{id}/stream      Reconnect to active SSE stream
    DELETE /sessions/{id}           Close session
    GET  /.well-known/agent.json    A2A Agent Card (auto-generated)
    POST /tasks/send                A2A task (synchronous)
    POST /tasks/sendSubscribe       A2A task (SSE streaming)

SSE events: {type: "text"|"tool_call"|"tool_result"|"error"|"done", ...}

Docker mode: --docker regenerates Dockerfile from manifest.yaml before
every build, ensuring spec.runtime.dependencies and host_dependencies
are reflected. Also loads .env and .env.local files.

--docker --trace starts a Grafana OTEL-LGTM container alongside the
agent (traces at Tempo, metrics at Mimir, logs at Loki, Grafana at :3000).

### zil push

Push a .zil archive to an OCI-compatible registry.

    zil push <archive> [options]

Options:
    --registry TEXT  OCI registry URL (required)
                     e.g. us-central1-docker.pkg.dev/my-project/agents

Resulting reference: <registry>/<agent-name>:<version>
Works with Artifact Registry, GHCR, ECR, Docker Hub.
Authentication uses ambient credentials (gcloud auth, docker login).

### zil deploy

Deploy the agent to Cloud Run.

    zil deploy [options]

Options:
    --project-dir DIRECTORY  Project directory (default: .)
    --from TEXT              Deploy from .zil archive or OCI registry reference
    --env-file PATH          Dotenv file with env var values (for CI/automation)
    --project TEXT           GCP project (or GOOGLE_CLOUD_PROJECT env var)
    --region TEXT            GCP region (or GOOGLE_CLOUD_REGION env var)
    --service TEXT           Cloud Run service name (default: agent name)
    --trace                  Enable Cloud Trace export
    --skip-evals             Skip pre-deploy eval check
    --allow-unauthenticated  Allow unauthenticated access to the Cloud Run service
    --memory TEXT            Cloud Run memory limit (default: 1Gi)
    --cpu TEXT               Cloud Run CPU allocation (default: 1)
    --output text | json     Output format (json for CI pipelines)

What happens during deploy:
1. Eval gate — blocks if below threshold (use --skip-evals to override)
2. Env resolution — from --env-file, process env, or interactive prompts
3. Dockerfile generation — if host_dependencies or runtime.dependencies exist
4. Cloud SQL auto-wiring — if SESSION_DB_URI contains a Cloud SQL path,
   auto-attaches via --add-cloudsql-instances
5. gcloud run deploy --source — builds via Cloud Build, deploys to Cloud Run
6. Cleanup — removes bundled files from local source tree

JSON output (--output json):
    {
      "agent": "my-agent",
      "version": "1.0.0",
      "service": "my-agent",
      "url": "https://...",
      "endpoints": {
        "adk_web": "https://.../dev-ui",
        "webhook": "https://.../webhook",
        "hitl_respond": "https://.../human/respond"
      },
      "cloud_sql_instance": "project:region:instance",
      "deployed_at": "2026-05-21T14:30:00Z"
    }

## SDK Reference

### zil.create_agent()

    import zil

    agent = zil.create_agent(
        tools=[],              # list of callable tool functions
        project_dir=None,      # str | Path | None — auto-detects from cwd
        name=None,             # str — override agent name
        description=None,      # str — override description
        model=None,            # str — override model string
        instruction=None,      # str — override composed instruction
        thinking_budget=None,  # int | None — Gemini thinking mode token budget
        enable_telemetry=True, # bool — auto-setup OTel tracing
        enable_guardrails=True,# bool — load & enforce guardrails at runtime
        enable_cost_tracking=True, # bool — track token usage from spec.cost
        raw=False,             # bool — return WiredAgent (for zil.Session)
    )

Returns a framework-specific agent (e.g., ADK LlmAgent) with:
- Name and description from manifest.yaml metadata
- Model resolved from adapters/llm.yaml
- Instruction composed from identity/persona.md + instructions.md + guardrails.yaml
- Telemetry configured from observability/config.yaml (if endpoint set)
- zil.config populated with spec.env declarations
- Guardrail engine loaded from identity/guardrails.yaml (agent._zil_guardrails)
- Cost tracker initialized from spec.cost (agent._zil_cost, zil.cost singleton)
- Sub-agents built from spec.agents (each with own identity, model, tools)
- Skills loaded from spec.skills dir, filtered per sub-agent
- Runtime deps parsed from spec.runtime.dependencies (ProjectContext.runtime_deps)
- Thinking config from spec.thinking_budget (propagated to all sub-agents)

### zil.config

Dict-like runtime access to declared environment variables.
Populated automatically during zil.create_agent().

    import zil

    root_agent = zil.create_agent(tools=[...])

    # Access by key (raises MissingConfigError if required & missing)
    api_key = zil.config["GOOGLE_API_KEY"]

    # With fallback for optional vars
    endpoint = zil.config.get("OTEL_ENDPOINT", "http://localhost:4318")

    # Check presence
    if "OPTIONAL_VAR" in zil.config:
        ...

    # Iteration
    for name, value in zil.config.items():
        ...

Resolution order:
1. .env and .env.local files (project root + module dir, never override existing)
2. os.environ (always wins)
3. Default values from spec.env declarations

Raises MissingConfigError for missing required vars without defaults.
Raises KeyError for vars not declared in spec.env.

### zil.sdk.hitl — Human-in-the-Loop

    from zil.sdk.hitl import request_human_input, HumanInputRequest

    async def approve_plan(plan: str, tool_context) -> str:
        request = HumanInputRequest(
            question="Review this plan.",
            context={"plan": plan},
            options=["approve", "reject", "modify"],
        )
        response = await request_human_input(request, tool_context)

        if response.choice == "__pending__":
            return "Waiting for human approval."
        return f"Human responded: {response.choice}"

HumanInputRequest fields:
    question          str        The prompt shown to the human
    context           dict       Structured context (plan, risk level, etc.)
    options           list[str]  Valid response choices (empty = free-text)
    interaction_id    str        Auto-generated UUID for correlation

HumanInputResponse fields:
    interaction_id    str        Matches the request
    choice            str        Human's selection or "__pending__"
    comment           str        Optional free-text comment
    timed_out         bool       True if no response received in time

Flow: tool calls request_human_input() → records in session state →
agent turn ends → human responds via /human/respond webhook →
runner resumes agent with updated state → tool reads response.

### zil.Session — framework-neutral invocation

    import zil

    agent = zil.create_agent(tools=[...], raw=True)  # returns WiredAgent
    session = zil.Session(agent=agent, workspace="/tmp/work")

    # Stream events
    async for event in session.stream("What files are here?"):
        print(f"[{event.type}] {event.text or event.tool_name}")

    # Aggregated response
    response = await session.send("Summarize the README")
    print(response.text)           # final text
    print(response.events)         # list[SessionEvent]
    print(response.session_id)     # session identifier
    print(response.token_usage)    # token consumption data

    session.close()

SessionEvent fields:
    type        "text" | "tool_call" | "tool_result" | "error" | "done"
    text        str | None     Text content
    tool_name   str | None     Tool name (tool_call/tool_result)
    args        dict | None    Tool arguments (tool_call)
    result      Any | None     Tool return value (tool_result)
    metadata    dict | None    Backend-specific data

SessionResponse fields:
    text          str              Final concatenated text
    events        list[SessionEvent] Ordered event list
    session_id    str              Session identifier
    token_usage   dict | None      Token consumption data

## Manifest Format (manifest.yaml)

    apiVersion: zil/v1
    kind: Agent
    metadata:
      name: my-agent            # kebab-case, 3-64 chars
      version: "1.0.0"
      description: Short description of the agent.
      labels:
        team: engineering
        domain: customer-support
    spec:
      runtime:
        language: python
        framework: adk
        llm:
          adapter: ./adapters/llm.yaml
        embedding:
          adapter: ./adapters/embed.yaml
        dependencies:                   # non-Python runtime dependencies
          - name: git
            type: apt
          - name: nodejs
            type: apt-nodesource
            version: "20"
          - name: gh
            type: apt-gh
          - name: pnpm
            type: npm-global
      thinking_budget: 2048            # Gemini thinking mode (optional)
      identity: ./identity
      skills: ./skills                  # path to skills directory
      evals: ./evals
      observability: ./observability
      deploy:
        target: cloud-run
        dockerfile: ./Dockerfile
      env:
        - name: GOOGLE_API_KEY
          description: Gemini API key
          required: true
          secret: true
      tools:
        mcp_servers:
          - name: jira
            transport: stdio
            command: node
            args: ["./tools/jira/dist/index.js"]
            source: ./tools/jira
            entry_point: dist/index.js
        host_dependencies:
          - nodejs
      agents:                           # multi-agent sub-agents
        - name: vta
          role: planner
          description: Plans implementation tasks.
          identity: ./agents/vta/identity
          llm:
            model: gemini-2.5-flash
            model_env_var: VTA_MODEL
          tools:
            mcp_servers: [jira]
            skills: [fd-explore-repo, fd-read-jira-task]
        - name: vtd
          role: executor
          description: Executes the plan.
          identity: ./agents/vtd/identity
          llm:
            model: gemini-2.5-flash
          tools:
            mcp_servers: [jira]
            skills: [fd-submit-changes, fd-run-tests]

### spec.agents field reference

    name            string    Unique identifier (lowercase)
    role            string    Short role label (planner, executor)
    description     string    What this agent does (passed to AgentTool)
    identity        string    Path to identity directory
    llm.model       string    Model override for this sub-agent
    llm.model_env_var string  Env var to override model at runtime
    tools.mcp_servers list    MCP server names from spec.tools.mcp_servers
    tools.skills    list      Skill names from skills/ directory

Model resolution: model_env_var → llm.model → root adapter fallback.

### spec.runtime.dependencies field reference

    name     string   Package name (required)
    type     string   apt | apt-nodesource | apt-gh | pip | npm-global (required)
    version  string   Version constraint (optional)

Installation order: apt → apt-nodesource → apt-gh → pip → npm-global.
curl/ca-certificates/gnupg auto-injected when apt-nodesource or apt-gh present.

### spec.skills

    spec:
      skills: ./skills

Points to the skills directory. Each subdirectory must contain SKILL.md.
Skills are loaded via ADK's load_skill_from_dir() and made available
as SkillToolset, filtered per sub-agent via spec.agents[].tools.skills.

### zil.cost

Module-level cost tracker singleton. Populated by create_agent().
Tracks raw token counts — no USD. Dollar pricing is delegated to
the Zil Runtime (coming soon) or your own billing layer.

    import zil

    root_agent = zil.create_agent(tools=[...])

    # Session totals
    zil.cost.total_tokens         # int — total tokens used
    zil.cost.total_input_tokens   # int — total input/prompt tokens
    zil.cost.total_output_tokens  # int — total output/completion tokens
    zil.cost.request_count        # int — number of LLM calls
    zil.cost.budget_remaining     # int | None — tokens left (None if no limit)
    zil.cost.by_model             # dict[str, TokenCounts] — per-model breakdown
    zil.cost.requests             # list[UsageRecord] — full request history
    zil.cost.reset()              # clear accumulators (keeps config)

### spec.cost manifest section

    spec:
      cost:
        max_tokens_per_request: 8192    # hard cap per LLM call (blocked if exceeded)
        max_tokens_per_session: 500000  # hard cap per agent session
        alert_threshold_pct: 80         # warn at this % of session budget
        track_by_model: true            # per-model token breakdowns

All fields optional. If spec.cost is omitted, tracking is passive (no limits).
Budget statuses: allowed | warned | blocked.

### spec.env field reference

    name          string   UPPER_SNAKE_CASE variable name (required)
    description   string   Human-readable description
    required      boolean  Must be set at deploy time (default: true)
    default       string   Fallback value if not provided
    secret        boolean  Sensitive data — masked in prompts (default: false)

## Identity

Three files in the identity/ directory:

### identity/persona.md
Markdown file describing who the agent is — personality, expertise, tone.

### identity/instructions.md
Markdown file describing how the agent behaves — rules, format, boundaries.

### identity/guardrails.yaml

Runtime-enforced guardrail rules. The GuardrailEngine checks input
(before LLM) and output (after LLM) using regex pattern matching.

    # Detection toggles (built-in pattern libraries)
    detection:
      prompt_injection: true   # block common jailbreak patterns
      pii_output: true         # block SSN/credit card in output
      pii_input: false         # optionally scan user input for PII

    # Custom regex patterns
    blocked_patterns:
      - name: internal_urls
        pattern: "https?://internal\\."
        target: output          # input | output | both
        severity: block         # block | warn | log

    # Keyword-based topic blocking (checked on input)
    denied_topics:
      - "competitor pricing"
      - "salary information"

    # Output length enforcement
    output_constraints:
      max_response_length: 4000

    # LLM instruction rules (not runtime-enforced, passed to system prompt)
    hard_blocks:
      - topic: illegal_activity
        description: Refuse requests for illegal activities.

    escalation_triggers:
      - condition: user_requests_human
        action: escalate
        message: "Connecting you with a human agent."

The engine is loaded automatically by zil.create_agent() and attached
as agent._zil_guardrails. It also converts hard_blocks and
escalation_triggers to natural-language directives in the system prompt.

### GuardrailEngine SDK API

    from zil.sdk.guardrails import GuardrailEngine

    engine = GuardrailEngine.from_config(guardrails_dict)
    result = engine.check_input(user_message)
    if result.blocked:
        return "I can't help with that."

    result = engine.check_output(agent_response)
    if result.blocked:
        return "[redacted]"

GuardrailResult fields:
    passed       bool — True if no blocking violations
    blocked      bool — True if action == "block"
    action       str  — "allow" | "block" | "warn"
    violations   list[Violation] — rule, description, severity, matched_text

OTel spans: guardrail.check.input / guardrail.check.output emitted
automatically when a tracer is active (via GuardrailCallback).

## Skills

Skills are reusable agent procedures in skills/{name}/SKILL.md files.
ADK's SkillToolset loads them and makes them available as agent tools.

    spec:
      skills: ./skills

Directory layout:
    skills/
    ├── fd-explore-repo/
    │   └── SKILL.md
    ├── fd-submit-changes/
    │   └── SKILL.md
    └── fd-run-tests/
        └── SKILL.md

SKILL.md format (markdown with # title, ## Procedure, ## Rules):
    # fd-submit-changes
    Submit code changes via a GitHub pull request.
    ## Procedure
    1. Create feature branch...
    2. Stage and commit changes...
    3. Push and open PR...
    ## Rules
    - Never force-push.
    - Use conventional commit format.

Per-agent filtering via spec.agents[].tools.skills allowlists.
Scaffold with: zil init my-agent --skills fd-submit-changes,fd-run-tests

## Multi-Agent

Declare sub-agents in spec.agents. Each gets its own identity, model,
MCP servers, and skills. The SDK wraps them as AgentTool instances.

    spec:
      agents:
        - name: vta
          role: planner
          description: Plans tasks. Never modifies code.
          identity: ./agents/vta/identity
          llm:
            model: gemini-2.5-flash
            model_env_var: VTA_MODEL
          tools:
            mcp_servers: [jira, github]
            skills: [fd-explore-repo]
        - name: vtd
          role: executor
          description: Executes the plan.
          identity: ./agents/vtd/identity
          tools:
            mcp_servers: [jira, github]
            skills: [fd-submit-changes, fd-run-tests]

Project layout for multi-agent:
    my-agent/
    ├── agents/
    │   ├── vta/identity/     persona.md, instructions.md, guardrails.yaml
    │   └── vtd/identity/     persona.md, instructions.md, guardrails.yaml
    ├── skills/               shared skills
    ├── identity/             root agent identity
    └── manifest.yaml

Scaffold with: zil init my-agent --agents vta,vtd --service webhook

## Runtime Dependencies

Declare non-Python runtime deps in spec.runtime.dependencies:

    spec:
      runtime:
        dependencies:
          - name: git
            type: apt
          - name: nodejs
            type: apt-nodesource
            version: "20"
          - name: gh
            type: apt-gh
          - name: pnpm
            type: npm-global

Dependency types:
    apt             apt-get install (standard Debian packages)
    apt-nodesource  Node.js via NodeSource (version = major version)
    apt-gh          GitHub CLI via official apt repo
    pip             pip install (non-requirements.txt packages)
    npm-global      npm install -g (requires apt-nodesource declared first)

Installation order: apt → apt-nodesource → apt-gh → pip → npm-global.
curl/ca-certificates/gnupg auto-injected when needed.

zil serve --docker regenerates Dockerfile from manifest before every build.
zil deploy generates custom Dockerfile with ordered RUN stanzas.

Preferred over spec.tools.host_dependencies for new projects.
host_dependencies kept for backward compatibility.

## Evaluation

### Eval suite (evals/baseline.yaml)

    eval_suite:
      name: baseline
      pass_threshold: 0.85
      cases:
        - file: ./cases/accuracy.yaml
          weight: 0.5
        - file: ./cases/tool_use.yaml
          weight: 0.3
        - file: ./cases/escalation.yaml
          weight: 0.2

### Eval case format

    name: accuracy
    cases:
      - input: "What is Zil?"
        expected_contains:
          - "framework"
          - "agent"
      - input: "Look up order #12345"
        expected_tool: lookup_order
      - input: "I want to talk to a human"
        expected_action: escalate

Scoring: suite_score = sum(case_group_pass_rate * weight).
Pack succeeds if suite_score >= pass_threshold.

## Observability

### Config (observability/config.yaml)

    observability:
      tracing:
        exporter: otlp
        endpoint: ${OTEL_EXPORTER_OTLP_TRACES_ENDPOINT}
        sample_rate: 1.0
      resource_attributes:
        service.name: my-agent

### How tracing works

zil.create_agent() reads observability/config.yaml, sets standard OTel
env vars (OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, OTEL_SERVICE_NAME,
OTEL_RESOURCE_ATTRIBUTES), then registers the OTLP exporter via the
framework backend's tracing setup.

The framework backend emits spans for: agent invocation, LLM calls, tool execution.

### Local development

    # Console output (no infra needed)
    zil serve --trace-console

    # Full observability stack (Grafana OTEL-LGTM)
    zil serve --docker --trace

    # Manual OTLP setup
    export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:4318
    zil serve --trace

### Production

    zil deploy --project my-project --region us-central1 --trace
    # Spans go to Google Cloud Trace

Or set OTEL_EXPORTER_OTLP_TRACES_ENDPOINT in .env for other backends.

### Compatible backends

Google Cloud Trace, Grafana OTEL-LGTM, Datadog, Honeycomb, Grafana Cloud,
Jaeger — any OTLP-compatible backend.

## Archive Signing

Zil supports signing .zil archives with cosign (Sigstore).

### Keyless signing (recommended)
    zil pack --sign
Creates a .bundle file alongside the archive (Sigstore bundle containing
signature, certificate chain, and transparency log entry). Authenticates
via OIDC (Google, GitHub, Microsoft). In CI, uses workload identity automatically.

### Key-based signing
    cosign generate-key-pair           # creates cosign.key + cosign.pub
    zil pack --sign --key cosign.key   # creates .bundle file

### Verifying signatures
    zil inspect --verify dist/my-agent-1.0.0.zil              # keyless
    zil inspect --verify dist/my-agent-1.0.0.zil --key cosign.pub  # key-based
Exit code 1 on failure.

### Push with signature
    zil push dist/my-agent-1.0.0.zil --registry ...
Automatically pushes .bundle alongside the archive if it exists.

## Packaging & Registry

Pipeline: zil pack → zil push → zil deploy --from

    zil pack                                          # → dist/my-agent-1.0.0.zil
    zil push dist/my-agent-1.0.0.zil --registry ...   # → OCI registry
    zil deploy --from <registry-ref> --project ...    # → Cloud Run

Archive contents:
    manifest.yaml, adapters/, identity/, evals/, observability/,
    my_agent/ (code), tools/ (if MCP sources), skills/ (if skills),
    BUILD_META.json, SBOM.cyclonedx.json, EVAL_RESULTS.json (if evals ran)

BUILD_META.json includes env_coverage:
    { "declared": [...], "resolved_locally": [...], "missing_locally": [...] }
